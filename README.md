# Лабораторные по защите информации

C++20, обычный `g++`, стандартная библиотека. Все команды ниже выполняются из корня репозитория.

## Первая лабораторная

```sh
mkdir -p build
g++ -std=c++20 -Wall -Wextra -Wpedantic -O2 labs/lab01/main.cpp common/crypto.cpp -o build/lab01
./build/lab01
```

В меню: быстрое возведение в степень, тест Ферма и алгоритм Евклида с ручным вводом, случайными или вероятно простыми числами. При вводе каждое число нужно писать на отдельной строке.

Проверки без сторонних библиотек:

```sh
g++ -std=c++20 -Wall -Wextra -Wpedantic -O2 labs/lab01/tests.cpp common/crypto.cpp -o build/lab01_tests
./build/lab01_tests
```

- [Короткое описание лабораторной](labs/lab01/README.md).
- [Подробный локальный отчёт](local/reports/lab01.md) — существует в этой рабочей папке, не входит в Git.


Поиск дискретного логарифма `a^x mod p = y` методом «шаг младенца, шаг великана». Есть ручной ввод и генерация разрешимого примера. Условие: `НОД(a,p)=1`; программа возвращает минимальный неотрицательный показатель либо сообщает об отсутствии решения.

```sh
g++ -std=c++20 -Wall -Wextra -Wpedantic -O2 labs/lab02/tests.cpp common/crypto.cpp -o build/lab02_tests
./build/lab02_tests
```

- [Короткое описание и примеры](labs/lab02/README.md).

Согласование общего ключа по схеме Диффи — Хеллмана. Есть ручной ввод, генерация параметров p=2q+1 и готовый пример из лекции. Программа показывает открытые значения и независимое вычисление одного и того же ключа двумя сторонами.

## Четвёртая лабораторная

```sh
mkdir -p build
g++ -std=c++20 -Wall -Wextra -Wpedantic -O2 labs/lab04/main.cpp common/crypto.cpp -o build/lab04
./build/lab04
```

Шифр Шамира для любых файлов: ручные параметры, генерация, отдельное расшифрование и пример лекции. Для файлов нужен простой модуль p>255. Сохраните показанный D_B для расшифрования. Программа не перезаписывает существующие файлы.

```sh
g++ -std=c++20 -Wall -Wextra -Wpedantic -O2 labs/lab04/tests.cpp common/crypto.cpp -o build/lab04_tests
./build/lab04_tests
```

- [Инструкция и файловый пример](labs/lab04/README.md).
- [Подробный локальный отчёт](local/reports/lab04.md).

## Где что лежит

| Папка / файл | Назначение |
| --- | --- |
| `lectures/` | Оригинальные лекции и задания, без изменений |
| `course_files/` | Примеры из курса с понятными именами; [описание исправлений](course_files/README.md) |
| `common/` | Общая библиотека для всех лабораторных |
| `labs/lab01/` | Меню и проверки первой лабораторной |
| `labs/lab02/` | Меню и проверки второй лабораторной |
| `labs/lab03/` | Меню и проверки третьей лабораторной |
| `labs/lab04/` | Шифр Шамира, работа с файлами, меню и проверки |
| `templates/lab/` | Простой макет для следующей лабораторной |
| `templates/report.md` | Единый план подробного отчёта |
| `local/` | Личные отчёты, исходные копии примеров, результаты проверок; игнорируется Git |
| `build/` | Исполняемые файлы; игнорируется Git |
| `AGENTS.md` | Постоянные правила работы с проектом |
| `openspec/` | Требования, решения, задачи и прогресс |

Числа ограничены по модулю значением `2 000 000 000`, промежуточные вычисления используют `long long`. Это покрывает требуемый в задании порядок `10^9`. Проверка Ферма даёт ответ «вероятно простое».

## Как продолжать через OpenSpec

Начать с [прогресса](openspec/progress.md). Требования к сделанному хранятся в `openspec/specs/`, решения и закрытые задачи — в `openspec/changes/archive/`. Для обычной компиляции OpenSpec не нужен.

Установленный OpenSpec инициализирован с `--tools none`: контекст хранится в файлах проекта, без установки дополнительных команд и навыков в настройки редактора. Правила их чтения записаны в `AGENTS.md`.

```sh
openspec list --specs
openspec validate --all --strict --no-interactive
openspec new change lab05-elgamal
openspec status --change lab05-elgamal
openspec instructions proposal --change lab05-elgamal
```

Последние три команды — для начала пятой лабораторной, она пока не реализована. После описания требований и реализации заполняются `tasks.md`, выполняются проверки и `openspec archive lab05-elgamal --yes`. Обновляется `openspec/progress.md`.

Это сохранённые сведения о проекте, а не автоматическая запись всех сообщений чата: решения и прогресс нужно поддерживать актуальными. Формат и команды: [официальная документация OpenSpec](https://github.com/Fission-AI/OpenSpec/blob/main/docs/cli.md).

Git локальный, ветка `main`, без удалённого репозитория. Папка `local/` не попадёт ни в коммит, ни в копию репозитория через Git; для сохранности отчётов нужна отдельная копия этой папки.
