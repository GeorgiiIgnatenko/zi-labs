# Файлы из курса

Все четыре исходных файла были текстовым кодом C++. Расширение `.hpp` было правильным только у `3.hpp`.

| Было | Стало | Что делает |
| --- | --- | --- |
| `1.hpp` | `random_prime.cpp` | Выбирает простое число меньше 100; проверяет перебором делителей |
| `2.hpp` | `binary_digits.cpp` | Выводит двоичную запись неотрицательного числа |
| `3.hpp` | `md5.hpp` | Реализация MD5 и преобразование хеша в восемь 16-битных чисел |
| `4.hpp` | `md5_example.cpp` | Пример вычисления MD5 для строки `I love ZI` |

`main()` означает самостоятельную программу, поэтому файлы 1, 2 и 4 получили расширение `.cpp`. MD5 подключается через `#include`, поэтому оставлен `.hpp`.

Минимальные исправления:

- Удалён Windows-зависимый `system("pause")`, подключены необходимые стандартные заголовки.
- В первых двух файлах русские комментарии уже содержали символы замены `�` в UTF-8: исходные буквы потеряны. Комментарии заново написаны по смыслу кода, перекодировка не помогла бы.
- Генератор в первом примере заменён на `<random>`, проверка простоты использует целочисленное условие `divisor <= number / divisor`.
- Второй пример раньше печатал биты с младшего к старшему и ничего не выводил для нуля. Теперь порядок обычный, для нуля выводится `0`, отрицательные числа отклоняются.
- В MD5 добавлены `<vector>`, `<string>`, `<cstdint>`, 32-битные типы и скобки в логических выражениях. Определения в заголовке отмечены `inline`, чтобы его можно было включать из нескольких `.cpp`.
- Пример MD5 подключает правильное имя с правильным регистром, печатает результат и освобождает массив из `HashToArray`.

Основной алгоритм MD5 сохранён. Старые `HashToVector` / `HashToArray` ожидают корректную строку из 32 строчных шестнадцатеричных символов, например результат `md5()`. `HashToArray` возвращает память, которую нужно освобождать через `delete[]`. Для обычного использования проще `HashToVector`. Эти функции возвращают **8 блоков по 16 бит**, а не 16 отдельных байтов; при переходе к лабораторным по подписи нужно свериться с заданием.

В первой лабораторной эти файлы не требуются. Здесь проверка простоты перебором из первого примера не заменяет требуемый тест Ферма.

## Проверка примеров из корня репозитория

```sh
mkdir -p build
g++ -std=c++20 -Wall -Wextra -Wpedantic course_files/random_prime.cpp -o build/random_prime
g++ -std=c++20 -Wall -Wextra -Wpedantic course_files/binary_digits.cpp -o build/binary_digits
g++ -std=c++20 -Wall -Wextra -Wpedantic course_files/md5_example.cpp -o build/md5_example
./build/random_prime
./build/binary_digits
./build/md5_example
```

Каждый `.cpp` собирается отдельно: у каждого свой `main()`. Исходные копии до исправлений находятся в `local/course_originals/`, вне Git.
