# Лабораторная №4 — шифр Шамира

Задание: [PDF, страница 3](../../lectures/Лабораторные%20работы%20ЗИ.pdf#page=3). Теория: [лекция 4, страницы 2–14](../../lectures/Лекция%204%20ЗИ%202026.pdf#page=2).

Программа шифрует и восстанавливает любые обычные файлы, независимо от расширения. Есть ручной ввод `p,C_A,C_B`, генерация всех параметров и числовой пример лекции.

## Сборка и запуск

Из корня репозитория:

```sh
mkdir -p build
g++ -std=c++20 -Wall -Wextra -Wpedantic -O2 labs/lab04/main.cpp common/crypto.cpp -o build/lab04
./build/lab04
```

| Пункт | Действие |
| --- | --- |
| 1 | Шифровать файл с ручными p,C_A,C_B; D_A,D_B вычисляются автоматически |
| 2 | Сгенерировать параметры и зашифровать файл |
| 3 | Расшифровать ранее сохранённый файл по D_B; p берётся из заголовка |
| 4 | Показать пример лекции: `10 → 14 → 15 → 19 → 10` |
| 0 | Выход |

Каждое число вводится на своей строке. Пути — целиком, без кавычек; пробелы и русские буквы допустимы. Каталоги для результата должны существовать, выходной файл — ещё нет. Оригинал и существующие результаты не перезаписываются.

## Как проверить на файле

Создать небольшой пример:

```sh
mkdir -p local
printf 'A' > local/shamir_original.bin
```

Выбрать пункт **1**, ввести `257`, `3`, `5`, затем пути `local/shamir_original.bin` и `local/shamir_encrypted.txt`. Программа вычислит `D_A=171`, `D_B=205`. **Сохранить D_B**: он потребуется даже после перезапуска программы.

Выбрать пункт **3**, ввести `local/shamir_encrypted.txt`, `local/shamir_restored.bin` и `205`. Сверить результат:

```sh
cmp local/shamir_original.bin local/shamir_restored.bin
```

Если `cmp` ничего не выводит и завершился с кодом 0, файлы совпали. Для повторения выберите новые имена результатов. Вместо примера можно взять PDF, картинку, архив или другой файл; восстановленному файлу укажите нужное расширение.

## Алгоритм и формат

Параметры: простое `p`, `2<C_A,C_B<p-1`, `НОД(C_A,p-1)=НОД(C_B,p-1)=1`. Обратные показатели вычисляются расширенным Евклидом:

```text
C_A*D_A mod (p-1) = 1
C_B*D_B mod (p-1) = 1
x1 = m^C_A mod p
x2 = x1^C_B mod p
x3 = x2^D_A mod p   ← сохраняем при шифровании
x4 = x3^D_B mod p   ← получаем исходный байт при расшифровании
```

Один исходный байт — одно число `m` от 0 до 255, поэтому файловый режим требует **p>255**, максимум 2 000 000 000. Числовой пример отдельно допускает `p=23`. Генерация выбирает точно проверенное простое p порядка миллиарда.

Зашифрованный файл — читаемый текст `SHAMIR1 p N`, затем N чисел x3, по одному в строке. N — число исходных байтов. Для байта `A=65` пример выглядит так:

```text
SHAMIR1 257 1
132
```

Секретных C,D в заголовке нет. Размер нужен для обнаружения недостающих и лишних блоков; это не контрольная сумма. Исходный и восстановленный файлы открываются в двоичном режиме. Обработка потоковая, без загрузки всего файла в память. При ошибке обработки программа удаляет созданный неполный результат.

Это учебная модель: обе стороны выполняются в одной программе, параметры выводятся для разбора, одна пара показателей используется для всего файла. Одинаковые байты дают одинаковые блоки; целостность и правильность ключа во всех случаях не гарантируются. В лекции (с. 5) рекомендуется менять пары для блоков; здесь сохранён простой режим с вводом одной пары. Это ограничение подробно объяснено в отчёте.

## Проверки и файлы

```sh
g++ -std=c++20 -Wall -Wextra -Wpedantic -O2 labs/lab04/tests.cpp common/crypto.cpp -o build/lab04_tests
./build/lab04_tests
```

- `main.cpp` — меню, ввод, демонстрация.
- `files.hpp` — потоковое чтение, три шага шифрования, отдельный четвёртый шаг, формат и проверки файлов. Небольшие `inline`-функции позволяют сохранить прежнюю команду сборки.
- `common/crypto.hpp`, `common/crypto.cpp` — обратное число, параметры и числовой протокол; используются степень, НОД и точная простота предыдущих лаб.
- `tests.cpp` — малые и большие числа, генерация, файлы и ошибки.
- [Подробный отчёт](../../local/reports/lab04.md) хранится локально и не входит в Git.
