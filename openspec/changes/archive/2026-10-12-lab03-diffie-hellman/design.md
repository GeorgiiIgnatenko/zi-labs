# Design

## Context

Лекция 3 задаёт простое p, первообразный корень 1<g<p-1 и секреты 2<=X_A,X_B<=p-1. Для генерации предложено p=2q+1 с простым q. Ограничение проекта p<=2000000000 делает точную проверку простоты и факторизацию p-1 перебором до корня достаточно небольшими.

## Goals / Non-Goals

**Goals:** повторить схему и пример лекции, дать ручной и случайный режимы, проверить параметры, вывести обе стороны обмена, написать отчёт и сохранить проверки предыдущих работ.

**Non-Goals:** сетевые соединения, шифрование сообщений, реализация атаки посредника, промышленные размеры ключей и длинная арифметика.

## Decisions

- `diffie_hellman(p,g,x_a,x_b)` возвращает y_a,y_b,z_a,z_b. Сначала вычисляются оба открытых значения; затем A использует только Y_B и X_A, B — только Y_A и X_B. Нельзя заменить вычисление второго ключа копированием первого.
- Контракт: простое 5<=p<=2000000000, первообразный корень 2<=g<=p-2, 2<=x_a,x_b<=p-1. Нижняя граница p=5 следует из диапазона g лекции. Ручной p не обязан быть вида 2q+1: в лекции это способ генерации, а не необходимое условие самого равенства ключей.
- Для точной проверки p вводится отдельный is_prime с перебором делителей. Этот алгоритм есть в лекции 1, страница 44. Функция fermat_prime не меняется и остаётся вероятностной. Для p<=2e9 достаточно проверить нечётные делители до 44721; условие d<=n/d избегает переполнения.
- `is_primitive_root(g,p)` для простого p проверяет `g^((p-1)/r) mod p != 1` для каждого различного простого делителя r числа p-1, как на странице 8 лекции 3. Факторы извлекаются простым циклом, без отдельной инфраструктуры.
- Генератор выбирает q из [500000000,999999999], проверяет q и p=2q+1 точным тестом; p получается порядка 10^9. Затем выбирает g из [2,p-2], пока g^q mod p != 1. Этого достаточно: возможные порядки 1,2,q,2q, первые два исключены границами g.
- Секреты генерируются из [2,p-1], как в лекции. Граничный секрет p-1 допустим в учебной модели и даёт открытое значение 1; это объясняется в отчёте. Не заявляется промышленная стойкость учебной генерации.
- g не обязано быть простым. Уточнение к фразе на странице 14: проверяется порядок элемента. Например, g=10 — первообразный корень по модулю 23.
- Все умножения остатков <4e18 и помещаются в long long. В рабочем алгоритме X_A*X_B не вычисляется: четыре вызова mod_pow остаются в прежнем контракте.
- Меню выводит секретные показатели только для учебной демонстрации, отдельно помечает открытые передаваемые значения и показывает оба результата общего ключа.

## Risks / Trade-offs

- Совпадение ключей само по себе не доказывает корректный выбор p,g; проверки параметров выполняются отдельно.
- Перебор до корня подходит для текущих учебных чисел, но не для больших криптографических модулей.
- При разрешённых лекцией крайних секретах возможен общий ключ 1. Формулы верны, но пример вырожденный.
- Диффи — Хеллман без аутентификации не защищает от подмены открытых значений; лекция рассматривает это на страницах 22–23. В лабораторной моделируется честный обмен двух сторон.
