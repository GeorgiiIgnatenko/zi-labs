# Design

## Context

Задание требует BSGS и числа порядка 10^9. В PDF задания напечатана оценка O(p log_2 p); лекция на страницах 64–65 даёт O(sqrt(p) log² p) для битовых операций. Нужно реализовать алгоритм лекции и явно объяснить различие моделей сложности.

## Goals / Non-Goals

**Goals:** понятный BSGS по формуле x=im-j; ручной и случайный режимы; проверяемые результаты, включая отсутствие решения; подробный локальный отчёт.

**Non-Goals:** обобщённый BSGS с сокращением общих делителей, длинная арифметика, новые системы сборки, реализация лабораторной №3.

## Decisions

- Контракт: `2 <= p <= 2000000000`, `1 <= a < p`, `0 <= y < p`, `gcd(a,p)=1`. Это включает случай простого p из лекции; составные модули также допустимы при взаимной простоте. При невзаимно простых a,p выбрасывается ошибка условия, а не ложное сообщение об отсутствии решения.
- Возвращается `std::optional<long long>`: число означает наименьшее неотрицательное решение, `std::nullopt` — решения нет. Для y=1 сразу x=0, для y=0 решения нет при допустимом основании.
- Выбираем m=k=floor(sqrt(p))+1. Небольшой целочисленный цикл находит m без округления вещественного корня; m²>p.
- Малые шаги `y*a^j mod p`, j=0..m-1, хранятся в `std::map<остаток,j>` как на странице 63 лекции. При повторении остатка сохраняется наибольшее j, чтобы x=im-j было минимальным в текущем блоке.
- Большие шаги `a^(im)` последовательно умножаются на заранее вычисленное `a^m`. Перебор i=1..m и максимальное j дают минимальное положительное решение; нулевое обработано отдельно. Ограничение x<p соответствует области поиска.
- Для взаимно простых a,p последовательность степеней периодична с периодом не больше p-1, поэтому все достижимые остатки встречаются при x<p. Сокращение на a^j в доказательстве законно только при взаимной простоте.
- Сложность со стандартным map: O(sqrt(p) log p) операций над машинными целыми и O(sqrt(p)) памяти; при учёте школьной битовой арифметики — O(sqrt(p) log² p), как в лекции. Попарное сравнение всех элементов не используется.
- Все числа — long long. Произведения остатков <4×10^18. При максимальном p размер шага 44722; индексы и их произведения безопасны.
- Генерация использует готовый отбор p через Ферма, выбирает взаимно простое a и показатель source_x, затем вычисляет y=mod_pow(a,source_x,p). Поиск получает только a,y,p, а исходный показатель выводится для сравнения и может отличаться от минимального ответа.
- Меню повторяет обработку строкового ввода первой лабораторной; математические функции не дублируются. Для задания границ сначала запрашивается p.

## Risks / Trade-offs

- Даже для простого p решение есть не для каждого y при произвольном a; выводится явное отсутствие решения.
- Отбор Ферма не доказывает простоту p, но корректность BSGS здесь обеспечивается взаимной простотой и не зависит от успеха вероятностного теста.
- Невзаимно простые a,p находятся вне контракта этого варианта. Например, 2^x mod 8=4 разрешимо, но требует другого обоснования или расширения алгоритма; программа честно отвергает такие входы.
- Исходный и найденный показатели могут отличаться из-за периодичности. Нельзя проверять генерацию простым равенством этих двух чисел.
