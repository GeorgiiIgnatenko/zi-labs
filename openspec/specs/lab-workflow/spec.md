# lab-workflow Specification

## Purpose
Сохранить простой единый способ разработки лабораторных, подробные личные отчёты и контекст проекта для продолжения работы в следующих чатах.

## Requirements

### Requirement: Простой макет
Каждая лабораторная SHALL использовать C++20, `labs/labNN/main.cpp` и `README.md`, общую библиотеку `common/` и сборку одной командой компилятора без внешних зависимостей.

#### Scenario: Сборка первой лабораторной
- **WHEN** выполняется команда из README с установленным g++ с поддержкой C++20
- **THEN** получается запускаемая программа `build/lab01`.

### Requirement: Локальные отчёты
Подробный Markdown-отчёт каждой лабораторной SHALL храниться в `local/reports/`, включать задание, теорию, разбор реализации, источники со страницами и запуск; вся `local/` MUST игнорироваться Git.

#### Scenario: Проверка отчёта
- **WHEN** создан `local/reports/lab01.md`
- **THEN** он доступен в рабочей папке и определяется Git как игнорируемый файл.

### Requirement: Контекст и прогресс
Проект SHALL хранить постоянные правила в `AGENTS.md`, контекст в `openspec/config.yaml`, требования в `openspec/specs/`, фактический прогресс в `openspec/progress.md`, завершённые задачи и решения в архиве изменений.

#### Scenario: Продолжение проекта
- **WHEN** начинается работа над следующей лабораторной
- **THEN** сохранённые файлы позволяют определить правила сборки, уже готовые функции, выполненные проверки и следующий шаг.

### Requirement: Материалы курса
Примеры курса SHALL иметь содержательные имена и расширения согласно содержимому; исходные PDF MUST оставаться без изменений.

#### Scenario: Переименование исходников
- **WHEN** в исходном файле находится самостоятельный main()
- **THEN** он получает расширение .cpp; подключаемая реализация MD5 сохраняет расширение .hpp.
